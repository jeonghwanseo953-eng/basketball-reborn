# RE:BORN 농구 동호회 웹 프로젝트 최종 통합 요구사항 정의서

## 1. 프로젝트 개요

### 프로젝트명

RE:BORN

### 프로젝트 목적

농구 동호회 운영을 위한 웹 서비스 구축.

현재 카카오톡 단톡방 기반으로 운영 중인 참석 투표, 경기 일정 관리, 팀 편성, 경기 결과 기록, 통계 확인, 회비 관리, 공지사항 전달 등을 웹으로 통합 관리하는 것이 목적이다.

개발자는 서버/인프라 지식이 많지 않으므로, 최대한 관리가 쉬운 구조로 간다.

## 5. 로그인 정책

카카오 로그인 연동을 고려한다. 참석 투표 및 사용자 식별 편의성을 위해 닉네임과 프로필 이미지를 사용한다.

초기에는 비회원도 이름을 직접 입력할 수 있도록 설계한다.

## 6. 회원 관리

회원 CRUD를 제공한다.

저장 항목:

- 이름
- 출생연도
- 키
- 포지션
- 지역
- 상태
- 메모

회원 상태:

- 정회원
- 게스트
- 휴식
- 탈퇴

## 7. 경기 일정 관리

경기 CRUD를 제공한다.

저장 항목:

- 경기일
- 장소
- 시작 시간
- 종료 시간
- 경기 방식: 2파전, 3파전
- 상태: 예정, 완료, 휴무
- 메모

공휴일, 체육관 휴관, 임시 휴무 등은 휴무 상태로 저장 가능해야 한다.

## 8. 참석 투표

참석 투표 CRUD를 제공한다.

투표 항목:

- 참석
- 불참
- 미정

입력 방식:

- 로그인 사용자는 자동 식별
- 비로그인 사용자는 이름 직접 입력 가능

기능:

- 다음 주 참석 투표 생성
- 투표 마감일 설정
- 참석/불참/미정 인원 자동 집계
- 2파전/3파전 진행 판단에 활용

## 9. 팀장 시스템

매주 팀을 짜는 사람이 달라진다.

팀장 역할:

- 참석 인원 확인
- 팀 드래프트
- 팀 구성 저장

경기별로 어떤 팀장이 팀을 구성했는지 기록 가능해야 한다.

## 10. 팀 구성 관리

팀 구성 CRUD를 제공한다.

팀 이름은 한글 기준으로 사용한다.

- 블랙
- 화이트
- 레드

운영 특징:

- 고정팀 아님
- 매주 팀 랜덤
- 색상 랜덤
- 구성 랜덤
- 운영자가 직접 팀 구성
- 운영자가 직접 수정

제외:

- 자동 팀 추천
- AI 밸런싱
- 자동 드래프트

## 11. 경기 운영 방식

하루 운동은 총 12쿼터 고정으로 운영한다. 쿼터 시간은 기본 8분이다.

### 3파전 운영 방식

참가 팀:

- 블랙
- 화이트
- 레드

대진 구성:

1. 블랙 vs 레드
2. 레드 vs 화이트
3. 블랙 vs 화이트

코트는 1개이므로 동시에 진행하지 않는다. 한 매치업을 끝까지 진행한 뒤 다음 경기로 넘어가는 방식이 아니라, 각 매치업을 쿼터 단위로 순환 진행한다.

예시:

- 1쿼터: 블랙 vs 레드, 레드 vs 화이트, 블랙 vs 화이트
- 2쿼터: 블랙 vs 레드, 레드 vs 화이트, 블랙 vs 화이트
- 3쿼터: 블랙 vs 레드, 레드 vs 화이트, 블랙 vs 화이트
- 4쿼터: 블랙 vs 레드, 레드 vs 화이트, 블랙 vs 화이트

총 12쿼터를 진행하며, 최종 점수는 각 매치업별 4쿼터 합산으로 계산한다.

### 2파전 운영 방식

참가 팀:

- 블랙
- 화이트

2파전이어도 하루 총 12쿼터는 동일하다. 블랙 vs 화이트 경기를 총 3세트 진행한다.

예시:

- 1세트: 1~4쿼터
- 2세트: 5~8쿼터
- 3세트: 9~12쿼터

각 세트별 승/패/무를 기록한다.

## 12. 경기 결과 관리

경기 결과 CRUD를 제공한다.

저장 항목:

- 경기
- 매치
- 쿼터
- 팀1 점수
- 팀2 점수

자동 계산:

- 승
- 패
- 무

개인 기록은 저장하지 않는다.

제외 개인 스탯:

- 개인 득점
- 리바운드
- 어시스트
- 블락
- 스틸

## 13. 통계 기능

통계 기능은 초기 구현 대상이다.

개인 통계:

- 개인 승률
- 출전 수
- 승/패/무 기록
- 평균 득점률
- 평균 실점률
- 최근 경기 기록

조합 통계:

- 같이 뛰었을 때 승률
- 특정 조합 승률
- 특정 조합 평균 득점
- 특정 조합 평균 실점

팀은 매주 랜덤 구성이므로 고정 팀 기반 통계는 중요도가 낮다. 우선순위는 개인 통계와 조합 통계이다.

## 14. 회비 관리

회비 관리는 초기에는 완성형 결제 시스템보다 구조/틀 중심으로 구현한다. 추후 토스페이먼츠, 간편 송금 연동이 가능하도록 확장 가능한 구조로 설계한다.

초기 기능:

- 월별 회비 생성
- 회차 수 관리
- 회비 금액 관리
- 회원별 납부/미납 체크
- 게스트비 관리
- 지출 내역 관리
- 월별 총 수입/총 지출/잔액 조회

지출 항목 예시:

- 대관비
- 점수판
- 농구공
- 휘슬
- 사물함
- 회식비

## 15. 공지사항 게시판

공지 CRUD를 제공한다.

저장 항목:

- 제목
- 내용
- 작성자 이름
- 작성일
- 상단 고정 여부

공지 예시:

- 회비 공지
- 휴무 공지
- 회식 공지
- 운영 룰 공지

## 16. 화면 구성

메인 화면:

- 다음 경기
- 최근 결과
- 참석 투표
- 공지사항

회원 화면:

- 회원 카드 목록
- 회원 등록/수정

팀 구성 화면:

- 블랙 / 화이트 / 레드 카드 UI
- 팀원 배정

결과 입력 화면:

- 쿼터별 점수 입력
- 매치별 결과 확인

통계 화면:

- 개인 승률
- 개인 득점률/실점률
- 조합 승률
- 조합 평균 득점/실점

회비 화면:

- 납부 현황
- 지출 내역
- 월별 정산
